# My Equipment Hub

A personal daily workspace for an equipment engineer. It keeps track of everything on your plate, lets you log work as you go, and writes your end-of-day report for you.

**Live page:** https://claude.ai/artifact/TdnYJBZk9ivqVWLDgSNWKK
**Source:** `equipment-task-hub.html` (single self-contained file, no build step, no dependencies)

---

## 1. Direction

This tool is being developed **for one person's own daily use** first. The goal is to boost an equipment engineer's productivity by:

- Showing what needs attention today, so nothing is lost across a wide scope of work
- Taking over menial work, above all the end-of-day report
- Keeping a permanent record of completed work

Sharing, community and team features are deliberately **out of scope for now**. They will be considered once the tool has proven it boosts productivity for its main user. Where the tool already stores data in a way that would support teams later (for example an `owner` field on each task), that is kept, but nothing is built around it yet.

## 2. Features

| Feature | Description |
|---|---|
| Today view | The default screen. Shows what needs attention today: overdue tasks, tasks due today, tasks you planned for today, tasks in progress and follow-ups that are due |
| Quick add | One line at the top to capture a task in seconds, with `@tool` for the equipment and `!` for high priority. New quick-added tasks go straight to Today |
| Plan for today | A ☆ button on any task to pull it into Today. Planning resets each day |
| Work log | One-line notes with a time stamp, added through the day. They feed the report |
| End-of-day report | Builds a ready-to-send report from today's completed tasks, work in progress, blockers, work log and plan for tomorrow. Editable before copying |
| Detailed task | Full form: report type, tool, tier, priority, due date, repeat, follow-up, notes, document links, pictures |
| Report types | Anomaly, PM, Hook-Up, Calibration, Modification, Improvement, Other |
| Tiers | **Technician** (hands-on), **Owner** (decisions, accountability), **Project** (improvement work) |
| Status | Open, In progress, Blocked, Done |
| Completed log | Done tasks move to their own tab, newest first, with completion date and full history. They can be reopened |
| Follow-ups | Optional follow-up date and note per task, flagged when due, with a "Follow-up done" button |
| Recurring tasks | Marking a recurring task Done creates the next occurrence |
| Document links | Link Excel, Word or any file stored in SharePoint, Google Drive or a network share |
| Pictures | Attach pictures to a task and click to enlarge |
| Editing | Every task can be edited after creation |
| Backup & restore | Download everything as a backup file, copy it as text, and restore from a file or pasted text (merge or replace). A banner reminds you when your last backup is more than a day old |
| Dashboard | Open, overdue, blocked, follow-ups due and done-today counts, plus a split of open work by tier |
| Theming | Follows light or dark mode |

## 3. A typical day

1. **Start of day:** open the page. The **Today** tab shows overdue work, what is due, and anything in progress. Use ☆ **Plan for today** on tasks in **All active** to build your list.
2. **During the day:** capture new jobs with the quick-add line. Type the job, add `@SRD` to tag the equipment and `!` if it is urgent, and press Enter. Note what you did in the **Work log**, such as "Replaced pump seal, leak check passed".
3. **Updating tasks:** change the status dropdown on a task. Set it to **Done** when finished and it moves to the Completed log.
4. **End of day:** click **End-of-day report**, enter your name once and any notes, review the text, and click **Copy**. Paste it into an email or chat.
5. **Back up:** click **Backup**, then **Download backup file**, and keep the file outside the browser (a cloud drive, email to yourself, a USB stick). Do this at least once a day while the tool holds your only record. If the red banner appears, your last backup is more than a day old.

### Quick add examples

| You type | Result |
|---|---|
| `Check chiller flow @CH01` | Task "Check chiller flow", tool CH01, medium priority, planned for today |
| `Fix door interlock @SRD !` | Task "Fix door interlock", tool SRD, **high** priority, planned for today |

Quick-added tasks default to type Other and tier Technician. Click **Edit** to change them.

## 4. End-of-day report

Generated with **End-of-day report**, dated with the current day, with your name if you entered one. It contains:

- **Summary:** counts of completed, in progress, blocked, overdue and total open tasks
- **Completed today:** each task with its type and tool
- **In progress:** with due dates
- **Blocked / waiting:** with the task notes
- **Work log:** today's log entries in time order
- **Plan for tomorrow / carry-over:** open tasks that are overdue or due by tomorrow, and follow-ups due by tomorrow
- **Notes:** the free text you typed for the day

Sections with nothing in them are left out, except "Completed today", which says "(none)". Document links on tasks are included. The text box is editable, so you can adjust wording before copying. **Refresh report** rebuilds it from the latest data and overwrites manual edits, so refresh first and edit last.

Your name is remembered. The notes are kept for the current day only and start blank the next day.

## 5. Which tasks appear in Today

A task appears on the Today tab if it is not Done and any of these is true:

- Its status is In progress
- It is overdue
- It is due today
- You planned it for today (☆ or quick add)
- Its follow-up date is today or earlier

Today is sorted with overdue work first, then by priority. Everything else open is under **All active**.

## 6. Recurring task logic

- Intervals: weekly (7 days), every 2 weeks (14), monthly (30), quarterly (90).
- When a recurring task is set to Done, a new Open copy is created.
- The next due date is the interval added to the original due date if that date is still in the future, otherwise the interval added to today.
- The copy keeps the title, type, tool, tier, priority, notes and document links. Pictures, follow-up, planning and history are not carried over.

## 7. Data and storage

Data is saved in the browser's `localStorage`. This suits a single user on one device, but browser data can be lost, so use the backup feature below.

| Key | Contents |
|---|---|
| `equip-task-hub-v1` | Tasks |
| `equip-hub-log-v1` | Work log entries |
| `equip-hub-settings-v1` | Your name, the day's report notes and the time of your last backup |

- Data stays in **one browser on one device**. It does not sync to your phone or another computer, except by restoring a backup there.
- Clearing browser data, a browser reset or reinstall, or some private-browsing modes will erase it. Restore from your latest backup if that happens.
- Browsers allow about 5 MB, shared by tasks, log and pictures. Pictures are resized to 900 px and compressed to help. The app warns if storage is full. See section 7b for what fits and what happens when it is full.
- The app asks the browser to treat its storage as persistent, which lowers the chance of automatic cleanup but does not protect against you clearing data.
- Tasks saved by earlier versions are upgraded automatically.

### Task data model

```json
{
  "id": 1729000000000,
  "title": "Chamber leak-rate check",
  "type": "Anomaly | PM | Hook-Up | Calibration | Modification | Improvement | Other",
  "tool": "Etcher 03",
  "tier": "Technician | Owner | Project",
  "pri": 1,
  "due": "2026-10-20",
  "owner": "Me",
  "status": "Open | In progress | Blocked | Done",
  "rec": 7,
  "notes": "",
  "fuDate": "2026-10-22",
  "fuNote": "Check pressure trend",
  "links": ["https://..."],
  "att": [{ "name": "photo.jpg", "d": "data:image/jpeg;base64,..." }],
  "pin": "2026-10-18",
  "hist": ["2026-10-18: created"],
  "doneAt": "2026-10-19"
}
```

`pri`: 1 = High, 2 = Medium, 3 = Low. `rec`: 0 = no repeat, otherwise interval in days. `pin` is the date the task was planned for. `owner` is kept for possible future team use and is not shown.

## 7a. Backup and restore

Open **Backup** in the top bar.

### Backing up

- **Download backup file:** saves `equipment-hub-backup-YYYY-MM-DD.json` through your browser. You are asked to confirm the save. Move the file somewhere safe outside the browser.
- **Copy backup as text:** copies the same data to the clipboard so you can paste it into a note or file. Use this if the download option is unavailable or blocked.
- The backup contains all tasks (including completed ones, links, history and pictures), the work log, and your settings.
- A red banner appears when you have data and have never backed up, or your last backup is more than a day old. **Back up now** starts the download.

### Restoring

1. Choose the backup file, or paste the backup text and click **Load pasted text**.
2. The app shows what the backup contains (date, number of tasks, completed tasks, log entries).
3. Pick how to restore:
   - **Merge (add missing):** adds tasks and log entries that are not already here, matched by their internal ID. Anything already here is kept unchanged, even if the backup has a newer version of it. Use this to combine data from two browsers or to recover something you deleted.
   - **Replace everything:** wipes what is in the browser and uses the backup instead. It needs a second click to confirm. Use this after your data was cleared.

Files that are not Equipment Hub backups are rejected without changing anything.

### Tips

- Back up at the end of each day, right after your end-of-day report.
- Keep the last few backup files, not just the latest, in case a bad state gets backed up.
- Test a restore once while you have little data, so you know it works before you need it.
- If the browser blocks the download, "Copy backup as text" always works.

## 7b. Storage capacity

How much this version can hold, so you can plan how heavily to use it. The figures below are estimates from the way the app stores data. They have not been measured in your browser.

### The limit

- Everything is stored in the browser's `localStorage`. Browsers typically allow about **5 MB per site** (around 5.2 million characters, counting keys and values together). The exact limit varies by browser and version.
- This is **one shared pool** for tasks, pictures, the work log and settings. It is not 5 MB per category.
- The backup file is not limited by this. It holds the same data, so it is at most as large as what is stored.

### What takes up space

| Item | Approximate size stored |
|---|---|
| Quick-added task | 0.3 KB |
| Fully detailed task (notes, link, history, follow-up) | 0.7 to 1.5 KB |
| Work log entry | 0.1 KB |
| One picture | **80 to 330 KB** (resized to 900 px and compressed, then stored as text, which adds about a third) |

Pictures are the deciding factor. One picture takes as much space as roughly 100 to 400 detailed tasks.

### What fits

| Content | Roughly fits |
|---|---|
| Tasks and log only, no pictures | 3,500 to 5,000 tasks, or about 50,000 log entries |
| Pictures only | About 15 to 60 pictures |

### How long until it is full

These assume 15 tasks and 10 log entries a day (about 13 KB a day without pictures) and an average stored picture of about 150 KB.

| How you use it | Fills in about |
|---|---|
| No pictures | 13 months |
| 1 picture every 3 days | 3 months |
| 1 picture a day | 1 month |

Your own numbers will differ. Treat these as a guide to which habit matters: pictures.

### What happens when it is full

- The app shows a "Browser storage is full" alert.
- **The change that triggered it is not saved.** When you add or edit a task with the form, the form stays open so you do not lose your typing. Other actions (changing a status, planning a task, deleting, adding a log entry) are visible on screen but are **lost if you reload the page**.
- Existing saved data is not damaged.

### Practical guidance

- Treat about **4 MB** as the working limit, since you cannot see how full it is and the real browser limit may be lower.
- Take a backup before attaching a run of pictures, and again afterwards.
- To free space, delete pictures from old tasks (**Edit**, then remove the picture) or delete old completed tasks after backing up. Completed tasks without pictures use very little space, so keep them.
- For documents and large images, use **document links** instead of attaching pictures.
- Expect the page to feel slower as pictures accumulate. Every change re-saves all tasks, pictures included, and every picture on screen is drawn when the page loads.

### Other ways data can disappear

These are separate from the size limit and are the reason backups matter:

- Clearing browsing data or site data
- Private or incognito windows, which discard everything when closed
- Safari, which may delete a site's stored data after about a week without visits
- Browser or device resets and reinstalls

### Not available yet

The app has no storage meter, so it cannot tell you how much space you have used. This is a candidate for the roadmap, along with a warning when you pass a set threshold.

## 8. Known limitations

- Data lives in one browser on one device, with no automatic sync. Backups are manual: you must download one yourself
- Pictures only: Excel, Word and other files cannot be uploaded, so use document links
- Storage is capped at roughly 5 MB, mostly consumed by pictures, with no usage meter (see section 7b)
- Network paths cannot be opened by a browser, so they appear as text with a Copy button
- The report is generated when you click, with no automatic scheduling
- The report covers the current day only
- No notifications or reminders
- No integration with MES, ERP or equipment logs

## 9. Roadmap (personal use first)

Ideas to make the tool more useful to a single engineer, in rough order:

1. **Report for a past day**, and a weekly or monthly summary built from the daily records
2. **Equipment pages:** per-tool history of issues, work done and pending actions
3. **Task templates** for recurring job types (PM checklists, hook-up steps)
4. **Improvement project tracking** with progress and time spent
5. **Handover notes** for shift changes
6. **Reminders** for due follow-ups and overdue work
7. **Automatic backups** to a cloud location, once the platform allows it
8. **Storage meter and warning** showing how full the browser storage is

Later, once the tool is proven for personal use: shared team data, sign-in, and sharing and community features.

## 10. Maintenance notes

- The app is one HTML file with inline CSS and JavaScript. To change it, edit the file and republish.
- Do not change the storage keys or remove task fields without a migration, or saved data will be hidden.
- Equipment types, tiers and statuses are plain lists in the file (`TYPES`, `ST` and the tier options) and can be edited directly.
- When hiding elements, make sure an element's own ID or class rules do not override the `.hide` class. This once caused a full-screen overlay to block the page.
